AutoFusion-Bench / AAAI 方向

模型什么时候该读、听、看？

我们现在要做的不是在别人数据集上刷几个点，而是用公开原始多模态数据搭一个新的 Benchmark 层： 测模型能否诊断模态缺陷、从其他模态补回信息，并在预算有限时选择正确的模态组合。

定位 五个任务 怎么构造 标注 评测 路线

核心定位：不是 missing modality 的旧题重做

旧问题通常问“缺了某个模态，最终分类性能掉多少”。我们的新问题问： 模型是否知道哪个模态坏了、坏在哪里、能不能补、该用哪个模态补、预算不够时该怎么选。

不要这样写

“我们研究多模态缺失，提出一个方法让 CMU-MOSEI/MELD 涨点。”这会被认为接近已有 missing-modality robustness。

应该这样写

“我们提出一个诊断式 Benchmark，评估 MLLM 在感知退化下的模态分诊、跨模态恢复和预算化路由能力。”

Benchmark 拆成五个任务层

这五层让模型的中间判断暴露出来。即使最后答案碰巧对了，也能看出它有没有选错证据、信错模态。

T1

模态健康诊断

判断 text、audio、video 是否 clean、corrupted、missing 或 conflicting。

T2

缺陷定位

指出损坏发生在文本 span、音频时间段、视频帧区间或区域。

T3

跨模态补偿

判断缺失信息能否从其他模态恢复，并给出来源和证据位置。

T4

预算化路由

在成本限制下选择 T、A、V、TA、TV、AV、TAV 中的可行组合。

T5

最终任务 / 拒答

给出情绪、情感、事件等答案；证据不可恢复时要能 abstain。

怎么做：公开原始数据 + 自己构造 Benchmark 层

路线 B 最稳：不从零采集，也不只是改别人数据集；用公开数据当底座，新增缺陷、标注、任务和评测协议。

Input

公开原始数据

优先选有 text / audio / video / label 的数据，如 CMU-MOSEI、IEMOCAP、MELD 或 AVQA。

Corrupt

可控感知缺陷

文本截断、音频加噪、视频遮挡、时间错位、跨模态冲突，全部记录 metadata。

Annotate

人工验证语义标签

人工确认 recoverability、evidence、oracle route、final answer 和 abstention。

Evaluate

多层评测协议

同时测诊断、定位、恢复、路由、最终任务，不只看 accuracy。

Analyze

失败模式分析

看模型什么时候信错模态、漏掉补偿证据、选了过贵路线或不该拒答。

标注策略：机器生成可验证标签，人工验证语义标签

LLM 可以做候选标注，但不能直接当 gold。Benchmark 可信度来自可复现 corruption metadata 和 human-verified labels。

自动生成 为什么可以自动
受损模态 脚本知道这次改了 text、audio 还是 video。
缺陷类型 corruption generator 记录 span deletion、noise、occlusion 等类型。
缺陷位置 文本 span、音频时间戳、视频帧区间都由脚本保存。
严重程度 SNR、遮挡比例、删除比例等是可控参数。
人工验证 为什么需要人工
可恢复性 要判断缺失信息是否真的能从其他模态语义补回。
补偿来源 需要确认应该看 audio prosody、video expression 还是 text context。
oracle route 要标出预算下最低成本且足够的模态组合。
拒答标签 多个模态都坏时，必须判断证据是否已经不足。

评测指标要能解释“为什么错”

最终分数只是最后一层。论文主表应该按 defect type、severity、recoverability、budget level 分层展示。

能力 指标 解释
诊断 per-modality F1 / defect-type macro-F1 模型是否知道哪个模态坏了、坏成什么样。
定位 text span F1 / temporal IoU 模型是否能找到坏的位置，而不是泛泛说“音频有问题”。
补偿 recoverability F1 / evidence hit rate 模型是否知道能不能补，以及该从哪里补。
路由 oracle-route match / regret / budget violation rate 模型是否在预算内选到了足够且不浪费的模态组合。
拒答 coverage-risk / false answer rate 证据不可恢复时，模型是否停止硬猜。
关键边界

MELD/CMU-MOSEI 这类数据可以用作底座，但不能只做 missing mask + final accuracy。 我们要新增的是 defect diagnosis、evidence-grounded recovery 和 cost-aware routing 这三层。

接下来七周的最小可行路线

先验证 schema 和失败模式，再扩规模。宁可 2k 条深标注，也不要 50k 条浅 missing mask。

第 1 周：文献和数据

整理 missing modality、MLLM evaluation、dynamic modality selection；检查 raw data、license 和下载可行性。

第 2 周：taxonomy + generator

冻结 text/audio/video 缺陷类型，写 corruption scripts，先做 30 条 end-to-end 检查。

第 3-4 周：gold pilot

200-300 个 clips，生成 1k-2k corrupted instances，人工验证 recoverability、evidence 和 route。

第 5-7 周：baseline + 论文表

跑 unimodal、full、oracle route、MLLM prompting 和 robust-fusion baselines，按切片做错误分析。
