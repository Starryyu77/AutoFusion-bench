多模态模型可能能诊断出音频或视频证据坏了，但在选择证据路线、回答或拒答时仍然做错。这就是 diagnosis-to-action gap。

1. 请专家重点核对什么

本次核对的目标不是评价模型结果，而是确认：这套人工标注字段和评分公式是否足以支撑一篇 benchmark / evaluation 论文的 pilot。

  1. v1 是否正确拆分了 modality_quality_status 和 modality_task_relevance，避免把“坏了”和“对当前问题没用”混在一起。
  2. post_corruption_answerability 与 cross_modal_recoverability 是否定义清楚。
  3. main_answerability=exclude_from_main 是否合理处理 partial / unclear 样本，避免 headline 指标被模糊样本污染。
  4. oracle_policy_action 使用 acceptable routes / preferred route / disallowed routes 是否比单一路由更严谨。
  5. headline 指标 conditional_policy_failure = P(policy_action_correct=false | triage_diagnosis_right=true) 是否真正测到了“诊断对但行动错”。
  6. 是否还缺少任何必须人工确认的字段，尤其是证据位置、可恢复性、拒答标签和风险策略。

3. v1 标注字段：专家需要确认的语义

人工 gold 字段

  • question_only_blind：排除只看题目和选项就能答的样本。
  • modality_quality_status：音频/视频的技术可用性。
  • modality_task_relevance：该模态对当前问题是否必要、充分、辅助或无关。
  • corruption_effect：污染造成无影响、换路线、降置信、不可回答或冲突。
  • post_corruption_answerability：污染后是否还能回答。
  • cross_modal_recoverability：是否能从另一个模态恢复答案依据。
  • oracle_policy_action：可接受路线、首选路线、禁用路线、是否拒答。

进入 headline 的限制

  • 只有 main_answerability=answerable 或 unanswerable 进入主表。
  • partially_answerable、unclear、高度策略依赖样本进入定性或风险分析。
  • 不能指出证据位置的样本，不应标成 recoverable。
  • 策略动作正确性不包含最终答案正确性。
  • 最终答案正确性另算为 task_execution_correct。

5. Scorer 现在怎么算

scorer 将每条样本拆成三类判断：诊断是否正确、策略动作是否正确、最终答案是否正确。

health_diagnosis_right:
  modality_quality_status correct

triage_diagnosis_right:
  modality_quality_status + corruption_relevance + corruption_effect correct

full_diagnosis_right:
  triage + answerability/recoverability + recovery_source correct

conditional_policy_failure:
  count(policy_action_correct=false AND triage_diagnosis_right=true)
  / count(triage_diagnosis_right=true)
指标 含义 是否 headline
health_diagnosis_macro_F1 模型是否看出音频/视频质量状态。 是
recoverability_macro_F1 模型是否判断出污染后是否还能回答、是否能跨模态恢复。 是
policy_action_accuracy 模型路线选择和拒答是否符合 oracle policy。 是
conditional_policy_failure 模型诊断对了，但策略动作仍错的比例。 核心 headline
rule_lift 固定规则使用同一份模型诊断，比模型自己行动提升多少。 是
false_answer_on_unanswerable 应该拒答时，模型仍然输出答案的比例。 是

7. 我们建议专家给出的结论格式

为了让反馈可执行，建议专家直接按下面四项回复。

  1. 是否可以冻结 v1 标注标准：可以 / 小修后可以 / 不建议。
  2. 必须修改的字段：指出字段名和原因。
  3. 5 条 smoke 中最危险的歧义：指出哪些样本不适合进入 headline。
  4. 扩展到 40 source / 160 instance 的条件：需要补哪些控制组、标注一致性或模型设置。

8. 如果核对通过，下一步怎么做

  1. 人工审完 5 条 smoke sheet，生成 smoke_annotations_v1.gold.jsonl。
  2. 用 v1 prompt 重新跑 Qwen diagnosis；旧 v0 smoke 只保留为 access / format 证据。
  3. 基于 frozen diagnosis 跑 model action。
  4. 生成 fixed-rule action。
  5. 用 scorer 跑真实 5-clip metrics，确认指标链路没有问题。
  6. 如果 5-clip 结果和标注一致性可解释，再扩展到 40 source / 160 corrupted instances。
