# exp-002 memory

Updated: 2026-06-09

## Current objective

Run the diagnosis-to-action pilot for unreliable audio-video evidence
governance under textual queries.

The core question is not only whether an MLLM answers a corrupted multimodal QA
item correctly. The pilot tests whether the model can diagnose unreliable
evidence, judge whether the task can be recovered from another modality, select
the right evidence route, and abstain when evidence is insufficient.

## Boundary

- Main substrate: AVQA / MUSIC-AVQA-style audio-video QA.
- MELD is diagnostic/control only, not the main positive substrate.
- Pilot target: 40 source items and about 160 scored corruption instances.
- Primary signal: diagnosis-to-action gap.
- Fixed-rule action and model action must consume the same frozen model
  diagnosis output.
- Do not treat generator corruption metadata as final task-conditioned gold
  labels; `modality_necessity` and `corruption_relevance` need human or
  adjudicated verification.

## Important observed issues

- The inner model-generated `model` field is unreliable. Use the outer logged
  model name from the runner.
- Defect localization from the smoke prompt is coarse and should be scored
  separately from high-level diagnosis.
- Some smoke examples reveal that modality necessity is task-conditioned:
  visual-looking questions can sometimes be recoverable from audio cues, and
  audio corruption can be irrelevant for a location question.
